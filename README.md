**Day012 - 生成AIで作るセキュリティツール100**

上杉暗号ツールは、字変四十八方式の上杉暗号を体験するWebツールです。
いろは48文字を右上から縦に並べた7×7の表で、各文字を「列番号→行番号」に暗号化・復号します。
標準表に加えて数字・かなの鍵を選び、表のハイライトで変換を確認できるインターフェイスです。

## ✨ 機能

- 「字変四十八」方式に基づく日本語換字暗号を再現
- 7×7のいろは順マトリクスによる座標変換（右上から縦、列→行）
- 暗号化・復号の双方向変換と、結果を入力に送る往復操作
- アラビア数字（5-7）・漢数字（五七）、数字の並べ替え・かなの鍵に対応
- 濁点・半濁点・小書き・カタカナの自動変換と、未収録文字のそのまま出力
- 使用文字のハイライト（色・太い枠・太字）と、動きを抑える設定への対応
- 和風のカード構成、ライト・ダークモード
- 日本語・英語の切り替え（画面の文言のみ。いろは48文字・漢数字・かなの鍵は扱う対象なので訳しません）
- 📱 レスポンシブ対応（1024px以上は入力・結果と表の2カラム、未満は縦積み）
- 結果のコピー、入力検証と通知、実行ごとのハイライトリセット
- いろは歌の配置と暗号化・復号過程の視覚化による古典暗号の学習
- ブラウザーだけで動作、インストール不要

## 📖 使い方

1. 入力欄に「てきみゆ」を入れる。
2. 暗号化・アラビア数字・標準（鍵なし）を選び、「実行」を押す。
3. 「5-7 6-3 6-6 6-4」と表のハイライトを確認する。
4. 「結果を入力に送る」を押して、復号結果「てきみゆ」を確認する。

数字表記や鍵を変えると、入力があり鍵が正しい場合は自動で再実行します。モードだけを変えた場合は前の結果とハイライトを消します。

平文の空白は、座標の区切りと見分けがつかないため暗号文に出しません。改行は保持します。入力上限はコードポイントで10,000文字です。

復号はアラビア数字・漢数字のどちらでも、全角でも受け付けます。漢数字は「五七六三六六六四」のように区切りなしでも復号できます。空きマス（7-7）と範囲外は「?」になり、座標として読めないトークンは区切りを足さずにそのまま出力して通知します。

## 🔑 鍵つきモード

列の鍵は右の列から、行の鍵は上の行から割り当てます。標準は両方とも「1234567」です。数字の並べ替えは7!×7!＝25,401,600通りです。「ランダムに作る」はブラウザーの乱数を使い、剰余の偏りを避けて並べ替えます。

かなの鍵は、いろは48文字から重複しない7文字を選びます。1句の中で文字が重なると復号が一意に決まらないので、「つゆにぬれつつ」「あまのかぐやま」は使えません。濁点などは清音に正規化してから重複を検査します。

かなの例「みかさのやまに／いでしつきかも」は阿倍仲麻呂の歌の下の句で、重複のない句の例として選んだものです。史料に載っている鍵ではありません。行の鍵は「いてしつきかも」として使用します。

| 鍵 | 列の鍵 | 行の鍵 |
|---|---|---|
| K1 | 3147526 | 2615374 |
| K2 | みかさのやまに | いてしつきかも |

| 鍵 | 平文 | アラビア数字またはかな | 漢数字またはかな |
|---|---|---|---|
| K1 | てきみゆ | 5-4 2-1 2-7 2-5 | 五四　二一　二七　二五 |
| K1 | ひみつのてがみ | 6-6 2-7 4-3 7-3 5-4 1-4 2-7 | 六六　二七　四三　七三　五四　一四　二七 |
| K2 | てきみゆ | やも　まし　まか　まつ | やも　まし　まか　まつ |
| K2 | ひみつのてがみ | にて　まか　さき　のき　やも　かも　まか | にて　まか　さき　のき　やも　かも　まか |
| K2 | いろは | みい　みて　みし | みい　みて　みし |

かなの鍵の暗号文は「やもましまかまつ」のように区切りなしでも復号できます。かなの鍵では数字表記を使わないため、数字表記の設定は無効になります。鍵は保存せず、URLにも載せません。

## 🔄 自動文字変換

いろは歌には濁点・半濁点・促音が含まれていないため、現代日本語の「が」「ぷ」「っ」などの文字はそのままでは暗号化できません。
本ツールでは、これらの文字を自動的に対応する清音に変換してから暗号化を行います。

## ⚠️ 注意事項

### 復号時の考慮点

- 復号結果は変換後の清音で表示
- 元の濁点・半濁点は復元不可
- 例：「がんばって」→暗号化→復号→「かんはつて」

### 意味の変化

一部の文字変換により、意味が変わる場合があります。

| 元の語 | 読み | 変換後の読み | 影響 |
|---|---|---|---|
| 時間 | じかん | しかん | 「歯科ん」のような音になる |
| 頑張って | がんばって | かんはつて | 意味が読み取りにくくなる |
| ラーメン | らーめん | らめん | 長音が消える |

### 推奨事項

- **学習・体験目的**: 文字変換機能により現代日本語も体験可能
- **歴史的再現**: より正確な体験には、変換が発生しない文章の使用を推奨
- **重要文書**: 現代暗号の使用を強く推奨

### 🎯 対応範囲

✅ **対応済み**

- 基本的な濁点・半濁点（か行、さ行、た行、は行）
- 促音（っ）
- 長音（ー）
- 拗音・小書き文字（ゃ、ゅ、ょ、ぁ、ぃ、ぅ、ぇ、ぉ）
- カタカナ・半角カタカナは清音のひらがなに変換

漢字・英数字・記号類はそのまま出力して通知します。変換前の濁点や長音、空白は復元できません。

## 📚 歴史的背景

この暗号は、上杉謙信の家臣・宇佐美定行が記したと伝えられる兵法書『武経要略』の「行間篇」に載るとされる「字変四十八」方式がベースです。
いろは48文字を7×7の表に並べ、文字を座標化するという仕組みは、古代ギリシャで記録された「ポリュビオス方陣」と同じ発想であり、日本における歴史的な暗号文化を象徴しています。

ただし、ポリュビオスが『歴史』第10巻に記したのは、秘密を守るための暗号ではなく、松明による信号の方法でした。
ギリシャ語の24文字を5枚の板に分け、衝立で仕切った左右の空間に松明を立てて、「何枚目の板か」と「その板の何番目の文字か」を伝えます。
いま「ポリュビオス方陣」と呼ばれる5×5の表は、ラテン文字を25マスに収めるためにできた後世の形で、その呼び名自体も後世のものです。
字変四十八と似ているのは「文字を座標の組で表す」という発想であって、古代ギリシャの暗号をまねたものではありません。
ポリュビオスの方法は [Polybius CipherLab](https://ipusiron.github.io/polybius-cipherlab/) で確かめられます。

### 出典と人物についての補足

字変四十八は、上杉謙信の軍師・宇佐美定行が『武経要略』に記した暗号として紹介されてきました。ただし、この伝承には次の留保があります。

- 宇佐美定行は、一次史料では存在を確認できない人物とされている。実在の越後の武将・宇佐美定満をモデルに、江戸時代の軍記のなかで作られた人物像だと考えられている（新沢1971、高橋1997・2007）
- 定行の活躍を伝える『北越軍記』は、紀州藩の軍学者・宇佐美定祐（1634〜1713年）の作と考えられている（高橋1997・2007）。定祐は初め大関姓を名乗り、貞享元年（1684年）に藩命で宇佐美姓に改めた（井上2020）。定祐が上杉謙信の感状などの文書を作ったと論じる研究もある（遊佐2007・2008）
- 『武経要略』は、国書データベース（国文学研究資料館）では分類が「兵法」、著者が宇佐美良賢（勝興）とされている。勝興（1590〜1647年）は定祐の父で、江戸時代前期の兵法家である（『日本人名大辞典』）。年紀のわかる伝本は、寛文6年（1666年）写・天和3年（1683年）写・天保15年（1844年）写など江戸時代のものが中心である。目録には天文5年（1536年）写とされる伝本も載るが、著者とされる勝興の生年より前の年紀であり、成立年代は確定していない

つまり字変四十八は、「上杉謙信の軍師の作」と伝えられてきた一方で、出典とされる『武経要略』は、江戸時代前期の越後流軍学者の著作として目録に載る兵法書です。謙信の時代に実際に使われたことを示す一次史料は、本ツールの作成にあたって調べた範囲では確認できていません。上杉暗号・字変四十八そのものを主題にした学術論文も、CiNii Researchでは見つかりませんでした（2026年9月検索）。

## 🔬 安全性分析

### 🔒 暗号方式の分類と基本特性

**暗号タイプ**: 単換字暗号（monoalphabetic substitution cipher）

- 各ひらがな文字が固定の座標ペア（例：「て」→「5-7」）に1対1対応
- 文字の置換関数が一定で変化しない

### ⚠️ 主要な脆弱性

#### 1. **頻度分析攻撃**

```
日本語の文字頻度（例）：
「の」「に」「は」「を」→ 高頻度
「ゑ」「ゐ」→ 現代では使用頻度極低

暗号文でも同じパターンが残る：
頻出する座標 → 「の」「に」「は」の可能性大
```

#### 2. **パターン分析**

- 同一文字の反復：「ここ」→「5-5 5-5」
- 語尾パターン：「です」「ます」の座標パターン
- 助詞の固定パターン：「は」「が」「を」の座標

#### 3. **鍵空間の問題**

標準の表はいろは歌の配置が固定で、実質的に鍵はありません。座標の読み方（列-行vs行-列）程度の違いしかない方式です。

鍵つきモードで数字の鍵空間を25,401,600通りに増やしても、単換字であることは変わりません。同じ文字は同じ座標になるため、頻度分析とパターン分析にはそのまま弱い方式です。重要な情報の保護には使わないでください。

### 🎯 具体的な攻撃シナリオ

#### **短文の場合（10-20文字）**

```
暗号文: 「5-7 6-3 6-6 6-4」
↓
1. 4文字の短い単語を推測
2. 「○○○○」パターンの日本語を辞書検索
3. 「てきみゆ」「ひみつの」等の候補
4. 1つでも当たれば4文字分の対応表が判明
```

#### **長文の場合（100文字以上）**

```
1. 頻度分析で「の」「に」「は」の座標を特定
2. パターン分析で語尾「ます」「です」を特定
3. 徐々に対応表を復元
4. 残りの文字を辞書攻撃で確定
```

## 🔒 セキュリティとプライバシー

ツールの画面は外部へのリクエストが0件で、入力・結果・鍵を送信しません。Google Fontsを含む外部リソースは読み込みません。ブラウザーに保存するのはテーマ設定と言語の選択だけです。

CSPをmetaで設定し、インラインスクリプト・インラインスタイルを使わず、通信をconnect-src 'none'で禁止しています。表示はtextContentとDOM構築で行い、鍵の種類・文字数・重複も検査します。referrerはno-referrer、外部リンクはnoopener noreferrerです。

metaではframe-ancestorsが無効なため設定していません。READMEのバッジや外部リンク先はツール本体とは別です。

## 💻 動作環境

モダンブラウザーで動きます。ローカルではdocs/index.htmlを直接開くfile://でも使用できます。HTTPで配信する場合は、次を実行して表示されたローカルURLを開いてください。

```sh
python -m http.server --directory docs
```

Node 22以上はテスト時のみ必要です。コピーはブラウザーのClipboard APIの利用条件に従い、使えない場合は結果を選択してコピーしてください。
